# Curriculum Modes

## Purpose

Use this reference to choose course scale, lesson sequence, and expected artifacts. Treat the numbers as defaults, not fixed requirements.

## Route negotiation

After initial field research, show the learner enough of the landscape to choose intelligently. Offer 2–4 routes that differ in substance, not merely lesson count: theory-first versus fast foundation and frontier work; broad survey versus a priority subfield in depth; paper-led versus practice-led; conceptual understanding versus operational independence.

For each route, state what receives depth, what is compressed or omitted, what papers are read closely, what practice is included, and what the learner should be able to do at the end. Recommend a route, but invite the learner to mix elements. Do not finalize the syllabus until the learner has responded, unless the original request already determines these choices.

## Comprehensive mode

Use when the learner wants durable command of a field.

- Typical scale: 12–24 lessons.
- Arc: field orientation → foundations → core mechanisms → method families → applications → evaluation → independent synthesis.
- Begin with basic concepts, history, and recent achievements.
- Delay detailed paper dissection until the learner understands the motivating problem.
- End with the learner comparing approaches and proposing questions or designs.

## Quick-start mode

Use when the learner needs useful competence soon.

- Typical scale: 4–8 lessons.
- Identify the smallest conceptual spine that prevents cargo-cult use.
- Teach the common workflow, essential vocabulary, one representative case, common failure modes, and where to go deeper.
- Omit historical or mathematical detail that does not affect near-term decisions.
- Never compress the course into a tool list.

## Project-led mode

Use when a real task motivates learning.

- Map the project into conceptual decisions and prerequisite gaps.
- Teach each idea shortly before it becomes useful.
- Keep teaching distinct from execution when the user separates those scopes.
- Use the project as a recurring example without narrowing all theory to one implementation.
- Record stable project-relevant conclusions only when authorized.

## Paper-led mode

Use when the learner wants to enter through the literature.

- Select one overview source, two or three landmark papers, and one or two current papers.
- Order papers by conceptual dependency rather than publication prestige.
- Give a prerequisite mini-lesson before each paper.
- Read figures as arguments: question → intervention → observation → conclusion.
- Compare papers only after each has been understood on its own terms.

## Refresher mode

Use when the learner has prior training but uneven recall.

- Start with a small diagnostic based on explanation and application.
- Skip fluent areas quickly.
- Rebuild gaps from their causal foundations.
- Focus on connections that have become important since the learner last studied the field.

## Hybrid selection

Common hybrids include:

- comprehensive foundations + project-led applications;
- quick start + later paper-led deep dives;
- refresher + current-research update;
- paper-led orientation + comprehensive foundations where gaps appear.

State the chosen hybrid in plain language. Avoid exposing an elaborate mode taxonomy unless it helps the user decide.

## Uneven depth allocation

Allocate effort by relevance rather than symmetry. Tag each unit with one depth:

- **Foundation:** only the concepts required for later work.
- **Survey:** main problem, core idea, and representative achievements; no practice required.
- **Working knowledge:** method logic plus a guided paper or exercise.
- **Deep study:** mechanistic detail, close paper reading, hands-on work, failure analysis, and an independent artifact.

A fast-frontier course commonly uses foundation depth for prerequisites, survey depth for historical methods, and deep study for the learner's target area.

## Theory–paper–practice patterns

Choose per unit: concept only; concept plus representative results; concept plus guided paper; concept plus paper plus practice; or practice plus theory repair for experienced learners. Practice may be a worked derivation, figure reconstruction, data analysis, code notebook, model inference, reproduction, design exercise, or experiment plan. Respect the user's boundary between teaching and execution.

## Route design template

For each course, define:

1. **Learner outcome:** what they should be able to explain, judge, or do.
2. **Conceptual spine:** 4–7 ideas that everything else depends on.
3. **Course arc:** 3–6 units with a clear reason for their order.
4. **Representative cases:** one sustained case per unit when possible.
5. **Paper schedule:** overview first, originals after prerequisites.
6. **Interaction points:** where answers can alter pace or depth.
7. **Completion evidence:** a teach-back, comparison, design, critique, or synthesis task.
8. **Effort allocation:** theory depth, paper depth, practice form, and explicit omissions for every unit.

## Lesson sizing

A lesson should answer one central question well. Split it if it requires multiple unrelated stories, too many new primitives, or several major mathematical frameworks. Merge lessons when one is only terminology with no explanatory arc.
